# 输入变体观察（test-design 实际应用）

这些是父 agent 要求的假设输入变体的设计响应，不是程序测试结果或实际业务缺陷。均依据本机安装 Skill 应用；没有执行 PASS。

| 变体/稳定观察 ID | 采用的响应 | 保留的边界与解除条件 |
| --- | --- | --- |
| TD-V01 无相关变更 | 若候选、依赖与预期均无变化，说明复核来源，保持原 ID 和设计，不机械新增用例。 | 只有仍适用的证据能复用；无变化不意味着此前 NOT_RUN 可变为通过。 |
| TD-V02 已有完整设计 | 若既有有效版本已覆盖旧入口、升级/保护及客户端合同，引用其原 ID，不再新增本文件的同义用例。 | 设计完整不自动代表执行已完成；真实当前 #368 尚未实现，不能把假设变体冒充现状。 |
| TD-V03 “保留旧别名”与“删除旧别名”冲突 | 固定两个来源及其版本，指出其对旧显式调用和旧 --only 行为相反；保留旧授权合同，不静默取最新字样覆盖批准需求。继续新名资料审查等不依赖冲突的部分。 | 旧别名验收期望未决，需需求拥有者明确批准具名破坏性迁移或撤回删除要求；设计者不能裁定。 |
| TD-V04 缺业务 oracle | 若“同一规范流程”只有实现自述，且原批准权限/检查点合同不可读，只能设计委托文件可达与字节来源关系；不能自造“业务等价”预期。记录已查 #368 和现有 spec-acceptance 仍缺原任务授权版本。 | 需要原任务明确授权/计划与验收负责人确认的合同；不能用实现和同源 Mock 的一致当权威判据。真实本次已能读取通用合同，缺的是最终调用任务记录。 |
| TD-V05 必需输入材料不可用 | 若旧安装 state/backup 无法取得，先记录所查旧 Git 版本、测试 fixture 定义及读取/构造条件。继续 fresh install 与文档审查设计，不伪造旧机器的历史快照。 | 从可读旧版本用真实安装器在隔离 HOME 重建已验证旧安装，或取得可核验且脱敏的旧运行材料；尚未运行前只称材料可读取/可准备。 |
| TD-V06 外部依赖只有 Mock | 若客户端发现或远端执行被 mock，仍可按明确合同设计本地分发断言；写明真实客户端可发现性、认证和服务行为未验证。把真实入口调用单列为尚需证据。 | 取得实际支持客户端的原生发现及受限调用轨迹；不为补证据扩大部署/付费/外部写权限。Mock 返回两个名称不证明客户端真的读了两种入口。 |

如输入已有 FAIL：保留原稳定 ID、结果、候选、证据和时间，在原记录追加修订理由及新尝试，不把“设计已完善”改写成 PASS。本次输入没有附具体历史结果表，因此未新增虚构 FAIL，也未声称历史全部通过。
