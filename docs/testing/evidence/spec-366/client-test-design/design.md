## 真实调用链与适用边界

`bootstrap.sh --only implement-batch` 原样转发参数 → `env.py main` → `build_plan` 按组件 ID 选择 → `plan_skill` 渲染正文及附件 → `plan_managed_file` 证明路径归属后写入 → 客户端读取已安装入口及其相对资料。旧 Skill 显式调用也是受影响的公开入口。`depends_on` 仅检查已存在能力；它不是自动安装。

身份/权限/归属适用性：本票涉及本地受管文件归属、备份与用户编辑保护，以及旧任务的既有执行授权；不涉及外部服务主体或资源 Owner 迁移。权威消费方依据是当前安装器的 `plan_managed_file`（env.py:586）、`link_guard`（env.py:614）及 `restore_guard`（env.py:1255），不是自造 Mock；它们保护实际路径、摘要及链接目标。客户端是否确实保留执行授权还需要真实受限调用观察，不能由 Markdown 字节比较证明。

无远端业务 API、业务数据库或付费测试数据要设计；状态顺序适用于安装→升级→还原→再安装，不能用单次 fresh install 代替。无需为无关重试/取消/网络时序生成组合用例。

- **数据与前置**：真实三个 Profile 的相关组件、固定候选的全部被引用 Skill 源文件、隔离 HOME 与 Sandbox；旧版材料可从上述 Git 对象取得，已确认源码可读取，尚未验证运行。最终候选及真实委托布局尚未提供，届时按实际布局冻结 fixture；不要预设规范正文一定在 sibling 目录。
- **动作**：沿用 Sandbox 的真实 `env.py apply --profile harness --only implement-batch` 和 `check`。从已安装的旧 `SKILL.md` 读取其实际委托引用，按该文件所在位置解析，继续读取规范正文与其要求的本地附件。直接新名安装作为同 fixture 的对照。实际 shell 薄壳兼容可复用同一隔离 fixture，从 `bootstrap.sh --profile harness --apply --only implement-batch` 再确认转发；无须另造安装器。
- **断言**：保留旧 apply/check/附录字节断言；增加（1）委托存在且可读，（2）所达正文来自当前唯一 canonical 源及正确客户端 frontmatter，（3）必需附件相对当前已安装正文可解析。不能只匹配字符串 `deliver-spec`、不能只看源仓目录存在、不能只断言路径可读。规范内容判据是已固定候选中唯一正文及批准合同；字节关系证明分发一致，不证明流程语义正确。
- **故障/正确对照**：同候选和同 fixture 仅在隔离源副本变更唯一委托目标为不存在路径；旧观察器预期仍通过，增强断言应在委托解析处失败，错误应明确包含被解析的入口与目标。还原单点变更后全新 HOME 的正确对照必须通过同组断言。另一个“存在但错误版本”可用冻结的旧正文副本，只有在覆盖唯一正文风险需要时执行，不为了数量必跑两种错误。
- **证据层级/缺口**：这是公开安装 CLI + 实际本地文件依赖的隔离入口测试，客户端发现被隔离 harness 绕过。它能证明分发及路径解析，不能证明模型会遵从该流程。最终布局、候选摘要、完整 fixture 和实际返回码待执行者补齐；本轮只是设计推演，没有故障运行或 PASS。

## TD368-UPGRADE-GUARD-01：旧受管安装的升级、还原与编辑保护

- **来源与不变量**：#368 升级、用户修改保护、plan/apply/check/restore 兼容。复用 `case_skill_overwrite`、`case_restore` 的现成动作及判据，补实际 legacy Profile 的迁移序列；泛用 demo-skill 通过不能独自证明新旧名称的登记键不会出错。
- **待检测错误**：fresh install 正常，但把旧名状态归属键改成新名后，旧文件变成“陌生文件”而升级不可用；或把 legacy 加进清理名单，删掉用户已修改的正文/附件；或 restore 后目录恢复了但后续旧名安装无法继续。

- **断言**：未编辑分支升级后新旧入口可达、旧附件有效，恢复后被本次升级触及的旧文件/状态对应旧快照，下一次旧名安装可继续；编辑分支必须保留用户字节并明确冲突/非通过，不因改名清理丢失；无关 Skill 文件摘要不变。安装器可能有部分成功，合同没有事务原子性，故不新增“任一冲突则全盘零写入”的断言。不得只测通用 guard helper。

## TD368-CLIENT-AUTH-01：新旧显式调用的范围与历史连续性

- **来源与不变量**：#368 的实际客户端两名称调用及在途授权/检查点合同。复用同一现存验收载体/历史 ID；换入口名不升级执行权限或清除旧 FAIL。
- **待检测错误**：文件路径都正确，但调用旧入口后客户端停留在壳上；或另建验收表丢失失败历史；或把“审查设计”当成允许实施、测试执行、部署。
- **前置与动作**：最终候选受管安装和一个实际支持客户端；使用同一固定任务输入与只到设计审查的明确授权，分别显式调用新旧入口，保留工具读取轨迹。输入中的历史用例/结果来自父 agent 现存载体，不能伪称合成 FAIL 是真实缺陷。若只能构造哨兵，它只检验保留行为，必须标记为合成。
- **断言**：旧入口的工具轨迹实际读旧壳→本轮 canonical 正文；两次引用同一载体、原 ID/失败记录仍在，无实现/测试/部署或新增 agent 副作用，未执行项不变为 PASS。不要以最终答复自述替代读取轨迹。期望由任务授权和固定原记录提供；真实服务身份并未纳入该调用。
- **证据边界/缺口**：真实客户端受限应用证据；不等于整个交付流程已执行，也不等于其他客户端/机器可用。本次 subagent 应用的是 test-design，不是这项两名称迁移验收，该项尚未执行。
