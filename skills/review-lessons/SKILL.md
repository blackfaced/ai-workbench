Consolidate the selected project's accumulated lessons. Default to the current project, not every repository or assistant memory. AIWB owns this procedure; the project owns its incidents, evidence, and maintained advice.

## Inspect and classify

Locate the existing lesson index and records. If none exist, report that rather than manufacturing lessons. Read all records in the requested bounded scope and inspect current code, tests, setup guides, and linked decisions relevant to their advice. Distinguish active, duplicated, superseded, automated, and applicability-unverified entries. Age alone does not prove obsolescence; a green test alone does not prove a failure mechanism is impossible.

Group by causal mechanism AND applicable boundary, not merely similar wording. Preserve materially different conditions. When a test or tool now enforces a lesson, link that check and its scope instead of repeating a broad instruction. When the subsystem is removed or a new rule supersedes the old one, record the current evidence and replacement. If a source is unavailable, keep the uncertainty rather than deleting the record.

## Consolidate and organize

Maintain one active explanation per applicable mechanism. Merge duplicated advice into the canonical record, preserving incident IDs, original evidence, exceptions, and links. Superseded records should become short redirects or leave the active index for an archive with stable links. Remove stale advice from the active guidance; preserve its provenance. Delete redundant files only when all unique content is preserved, links are repaired, and history/recovery is available. Never discard untracked-only evidence as if Git preserved it.

Use the existing record format; if none is established, consult the installed `reflect-bug` lesson outline (source: `skills/reflect-bug/references/lesson.md`). Organize the active index by observable triggers/modules so implementation agents can retrieve only relevant lessons. Record last verification and applicability limits. Keep project-specific improvements in that project's tests/guides; proposed repairs go to its Issue tracker, not checklist status in the lesson index.

Review documents as a coherent diff: every removed active entry maps to a preserved canonical/archive/replacement entry, every internal link resolves, and substantive conclusions cite inspected evidence. Report counts, merges, retired advice and its reason, uncertain entries, and changed paths. Reflection/maintenance authorization does not authorize code fixes, changed CI thresholds, promotion into global Skills, assistant-memory edits, or cross-project publication.
