# Self-test Report

Domain: coding

把项目已有测试结果整理成可复核的验收证据。输出使用项目已有载体；本 Skill 的正文与模板以 AI Workbench 为真源，不要求新建报告系统、测试框架或全局门禁。可独立用于编写、更新或审查报告，不启动测试、部署、实施编排或额外 agent。与 deliver-spec 配合时，本 Skill 维护结果归一化、证据审查和报告细则；原流程继续拥有验收设计、执行权限、角色分配和最终接受责任。只引用项目已有验收记录，不复制第二份结果真源。

## 模式与硬边界

开始时选择一个模式，并在产出中注明：

- **compose**：从项目既有验收记录、原始运行结果和证据生成一页可扫读摘要。
- **update**：把新候选、新 Attempt 或新证据映射回相同 Case ID，保留旧结果、复测关系和证据有效性。
- **audit**：只审查现有报告是否错绑候选、遗漏失败、越过证据边界或混淆角色；输出发现和最小修正建议。

三种模式都不得启动或批准测试、补数据、部署、付费调用、共享环境写入或新的 agent。发现缺证据时只记录结构化证据缺口：`case_id`、缺什么、影响哪条结论、建议执行者、最小补测范围、所需授权和恢复条件；由 Tester、deliver-spec 或项目执行流程决定是否运行。报告生成、执行器结束、会话完成或进程退出零都不等于测试通过。

## 1. 确认范围与版本

先读取当前需求及后续已确认的调整、候选改动、现有报告和原始测试结果。区分本次交付、明确延期及尚未决定的范围；旧文档与最新决定冲突时标出来源，不悄悄选一个。

记录需求与验收设计版本、候选 SHA、目标/比较基线、实际被测代码身份、测试代码身份、环境、执行时间和运行编号。未提交代码用 base SHA 加 patch/文件摘要标识，不把后来提交的 SHA 自动套在旧结果上。服务端部署另记录部署物身份；构建号、日志或关联信息不可得时写明无法确认。端口和截图文件名不能代替版本身份。

**完成条件：** 每项拟写入结论的结果都能指出测试对象；身份不明的结果只作历史参考，证据有效性标 UNVERIFIED，不改写原始执行状态，也不计作当前验收通过。

## 2. 对齐 Case、Attempt 与执行来源，识别证据缺口

优先读取项目唯一验收记录，按相同的稳定 Case ID 和设计版本汇总；只有项目没有覆盖表时才在报告中创建后备表。每项结论必须能沿以下链路回溯：需求/合同版本 → Design Revision → Case ID → Attempt → Candidate Identity → Environment → Executor / Role → Source Type → Transport Status → Raw Status → Canonical View → Actual Observation → Oracle Source → Evidence References → Evidence Validity → Reviewer。无法映射到稳定 Case ID 的结果只能列为补充观察，不能计入覆盖率或最终通过统计。

对每个 Attempt 记录执行来源与传输状态：执行器/模型或人员、执行角色、`source_type`（如 repo_test、qa_assistant、ci、manual）、候选与环境、执行时间、原始状态、实际观察、判据来源和证据引用。外部执行器的 `transport_status`（completed、interrupted、timeout、unknown）与测试状态分开；`completed`、生成报告或机器人回复不能映射为 PASS。同一 QA 助手参与设计又执行时，结果可以作为执行证据，但不自动构成独立 QA。

按改动风险核对公开入口、正常路径、相关边界、依赖失败及受影响兼容路径。只审查本需求相关场景，不机械扩成全项目矩阵。涉及异步、付费或持久化时，分别检查结果归属、待发请求、已发请求和实际写入；不能由一个“关闭测试”推断全部成立。

当改动可能影响既有行为时，向后兼容优先于可维护性、去重和代码简洁，除非需求明确批准迁移或破坏性变更。报告必须列出旧可观察合同、实际受影响的调用方/模块、特征或回归用例、前后实测值、兼容策略（例如适配器、Wrapper、Optional 字段、默认关闭开关或保留旧路径）、回滚方案及尚未验证的兼容边界。不要只按改动文件列表声明影响面；共享组件、Hook、配置、登录态/权限、持久化数据、错误语义、兄弟模块以及轮询/重试/性能边界均按实际调用关系评估。

旧路径未测试、新路径通过、构建成功、源码检查或“内部重构”说明，都不能证明向后兼容。不得为了让候选通过而删除、改弱或重写旧行为断言。无可执行证据的兼容项保持 BLOCKED/NOT_RUN；只有显式批准的具名迁移缺口才能按批准边界交付，并记录责任人、迁移和回滚条件。

保留项目验收记录的原始执行状态；新记录沿用以下口径：

- **PASS**：对应断言实际执行且满足预期，证据身份和范围明确。
- **FAIL**：实际执行，预期未满足；保留失败结果与后续复跑关系。
- **BLOCKED**：前置条件、权限、环境、身份或预期判据不可用；记录已检查的依据和解除条件，不要求为了证明阻塞先执行不安全操作。
- **NOT_RUN**：未尝试执行。执行记录本身缺失时写“未知”，不能推断没有执行。

另列证据有效性：**VALID**（适用于当前候选及断言）、**STALE**（已知变化使其失效）、**UNVERIFIED**（缺证据、身份不明或断言不足，注明具体原因）。历史 PASS + STALE/UNVERIFIED 不计入当前验收通过。**N/A** 是适用性，不是执行结果：当前合同明确不适用时给出理由；延期项另列，不藏在通过率中。不覆盖项目已有状态体系，不把证据缺口计作实测失败。

先复用可对应当前对象的证据。需要跨提交复用时比较影响范围，注明来源 SHA、未重跑项目及理由；相关生产代码、测试、依赖、配置或环境变化时重新验证受影响项。仅修改报告文字或更换已存在的截图，不触发全量构建。新增已确认缺陷时保留原套件 PASS，并同时列出缺陷，不能把未跑的新用例算入失败数。

**完成条件：** 每个验收点都能引用原始状态与依据；缺口已形成最小证据请求而非被本 Skill 执行。真实付费/共享环境操作沿用已有授权；缺授权不改变原始状态，独立且已有证据的核查继续。

## 3. 核验证据能证明什么

| 要证明的结论 | 合适的证据 | 常见不足 |
|---|---|---|
| 界面内容、布局、可操作性 | 对应状态截图 + 实际控件/交互断言 | 只看截图无法确定按钮是否可点击 |
| 状态转换、先后顺序 | 分阶段断言，必要时配状态组图或录屏 | 用完成态截图证明等待期禁用或提前进入 |
| 请求数量、隔离、重试范围 | 按对象/轮次记录请求参数与计数 | “请求正确”没有实测值，或用 UI 代替网络证据 |
| 持久化、无覆盖 | 写入断言 + 保存后重新读取/刷新 | 只验证当前本地草稿 |
| 迟到响应与取消 | 可控挂起/释放，确认旧响应被处理后再检查结果、后续请求和写入 | release 后立即查空 DOM，或固定 sleep 后假定完成 |
| 向后兼容 / 既有调用方 | 旧入口的特征/回归测试 + 共享组件各已知调用方的前后实测；配置/权限/数据/错误/副作用分别检查 | 只验证新路径、编译成功或改动文件，未跑旧路径和兄弟模块 |
| 性能改善 | 固定样本/环境/模型/规模，明确起止事件和前后耗时 | “立即”“很快”，或用 Mock 延迟推导真实收益 |
| 真实服务兼容/输出质量 | 对应服务的真实链路及可复核输出/判据 | 用确定性 Mock 证明服务、模型质量或计费正确 |
| 身份、权限、资源归属 | 从凭据来源到权威消费方的有效 principal、resource owner、权限与持久化效果；使用独立于候选实现和同源 Mock 的依据 | 只看字段名、同源 Mock、实现与测试共用同一逻辑或一次成功响应 |

图片与证据条目绑定测试点、状态和运行身份。小报告逐图检查；图片多时先检查全部元数据，再按主链路、失败/恢复和最近变更抽看，明确抽查数量与未核验范围。发现错图/旧图则扩大到同批次或同结论证据。旧图可用于历史比较，标明版本；一个截图可支持多个确实可见的断言，无需每行机械配图。UI 关键行为提供截图或录像引用；无法采集时明确缺口，不用加载完成截图替代交互证据。

审查报告时抽取关键用例的实际断言和原始结果。检查是否等待异步条件、是否真正操作目标入口、是否只断言“有新 chunk”却声称某模块懒加载、是否只检查部分语言却声称全部页面验收。把问题定位为报告失效、断言不足或已复现功能缺陷，不从错误报告推断作者动机。观察与归因分开；没有对照或诊断证据时，失败原因写“未确认”，不能由其它环境通过反推本地失败无害。

每次报告都必须记录**身份合同核验**：`applicable=true/false/unknown`、判断依据、权威证据、未决缺口和门禁结果。`applicable=true` 但缺少权威证据，或适用性为 `unknown`，均不得给出准入通过；`applicable=false` 只有写明为何当前改动不涉及身份、权限或资源归属时才可通过，理由缺失时门禁仍为不通过。同源 Mock、字段名一致、实现与测试使用同一逻辑不能证明身份合同。

当业务仓自动化、QA 助手、CI、人工观察或排查工具之间结论不一致时，单列证据冲突：来源 A、来源 B、共同绑定的 Case/候选/环境/时间窗、冲突点、当前更强来源、选择依据和未决影响。只有取数与判据相互独立且对象一致时才称为独立验证；否则标为补充观察或交叉线索。冲突未解决时不得用多数票或执行器名气推导 PASS。

**完成条件：** 结论不超过证据能力；可分享产物使用团队可访问的链接/附件，脱敏身份与凭据。仅有本机文件时明确访问限制，不声称团队已可复核。

## 4. 编写或更新报告

新建或重组报告时使用 [报告模板](assets/report-template.md)，默认只生成一页摘要和原记录索引。已有报告继续按原有标题、布局和项目约定原地更新；不要仅为采用 V2 模板而改版，旧版“运行身份”“角色与轮次”“需求覆盖”“自动化与构建记录”“关键证据”“开放问题与未验证范围”等结构仍受支持。只有出现多仓/多候选/多环境、历史失败与复测、向后兼容风险、付费/权限/持久化风险、多个执行来源冲突，或项目没有既有验收记录时，才展开完整结果或兼容矩阵。优先在项目既有验收文档中生成摘要和索引；确需独立报告时链接原记录，不复制维护完整矩阵。正文优先写本轮结论、Case 计数、证据有效性、身份合同、冲突、开放问题和准入摘要，详细日志与历史对照放附件。复用已有观察，不为填报告新增 agent 或盲目全量复跑。

把每条外部结果归一化为以下报告视图，字段不可得时写未知及原因，不猜值：

`Case ID | Design Revision | Attempt | Candidate Identity | Environment | Executor / Role | Source Type | Transport Status | Raw Status | Canonical View | Actual Observation | Oracle Source | Evidence References | Evidence Validity | Reviewer`

`Canonical View` 只用于报告汇总，不覆盖原记录。优先原样保留 PASS、FAIL、BLOCKED、NOT_RUN；记录缺失或来源只给 unknown 时计入“未知”，不放入 PASS/FAIL/BLOCKED/NOT_RUN 分母。`skipped` 只有明确证明未尝试目标断言时映射 NOT_RUN；因权限、环境、身份、数据或判据不可用而跳过时映射 BLOCKED；`error` 若目标断言已经执行且观察值不满足预期才映射 FAIL，否则按阻断原因映射 BLOCKED，无法判断则为未知。每次映射保留原值和理由。无法判定断言是否执行、候选是否正确或证据是否有效时，Canonical View 不得为 PASS。

分别标明**开发自测、外部执行来源、独立 QA、最终集成验收**的执行者、角色、轮次、候选和结论；同一执行者的自查不冒充独立 QA，QA 助手同时设计与执行也不自动具备独立性。独立代码 review 标注“审查”，不能当作实际执行测试。分别给出自动化、真实联调及本阶段提测/合入条件的判断；Mock PASS 保留 Mock 标签，平台绿色但未执行测试不记为测试通过。报告沿用目标项目的验收权限；Tester、项目父流程或项目指定接受者作最终准入判断，本 Skill 不自行宣布接受或另建状态真源，缺失角色证据如实列出。

更新已有报告时逐项检查：

1. 需求/设计版本是否变了：修正当前结论，保留稳定 Case ID，将旧预期和旧图移到标明版本的历史部分。
2. Attempt、候选或环境是否变了：只更新受影响 Case；保留首次失败、复测链和未受影响证据的复用依据。
3. 测试集合是否变了：从原始结果汇总通过、失败、跳过、未执行；共同用例比较与新增/删除用例分开，合并后去重，注明执行失败/中断。
4. 证据是否变了：只把确有来源的新图/日志关联到当前结论，说明复用项；不能只替换顶部 SHA 与总数。
5. 新缺陷、证据冲突或身份合同缺口是否进入摘要：写触发条件、影响、状态、证据、阻断或延期依据及已有跟踪位置；没有接受延期的依据就写待决定，不擅自宣布不阻塞。
6. MR 与报告是否一致：MR 留行为变化、需求链接、验证分层、开放问题和报告链接；完整矩阵只维护一份。

`audit` 模式至少检查：候选/部署物错绑；transport completed、会话结束或退出零误写 PASS；Mock 冒充真实联调；遗漏 FAIL/BLOCKED/NOT_RUN；身份合同缺权威证据；QA 助手被误标为独立 QA；Case ID 或设计版本不可回溯；证据冲突被隐藏；准入结论超过证据。只修报告可证明的问题；功能缺陷、缺测和执行需求分别退回项目流程。

分别记录**报告生成、发布状态、目标读者访问**：入口与必要证据链接、预期读者、授权内的访问检查及限制。作者能读、HTTP 成功或远端绝对路径不证明目标读者可访问。无发布授权时保留完整本地报告，标明“本地就绪，发布待办”；访问未检查或被拒绝分别如实标明，不为获得公开链接擅自发布私有证据。已有本地报告但只有聊天 PASS，或只有旧候选报告，均应补入口和适用性分析。

交付回复及已授权的需求/MR 更新附报告入口与访问/发布状态，包括有失败或未验证项的交付。缺少约定报告意味着交付材料不完整，测试总数不能替代它。报告写作/审查本身不授权发布评论、更新平台状态、修业务代码、运行补测或创建跟踪事项；用户已有明确授权时仍由对应项目流程执行，self-test-report 只消费其结果。

报告的准入摘要给项目接受者以下输入，而不是代替其决定：状态计数与关键 Case ID、最终候选与环境、证据有效性、身份合同门禁、未解决冲突、开放 FAIL/BLOCKED/NOT_RUN、获批例外和最小证据缺口。报告生成不等于项目验收；有任一必需项未通过、身份合同门禁未通过或冲突影响关键结论时，准入摘要只能写“不满足/待决定”，不得写接受。

**完成条件：** 最新需求/设计版本、Case ID、候选、环境、Attempt、原始状态、证据有效性、图片和开放问题一致；最终说明哪些由本轮核验、哪些复用、哪些未验证。按项目门禁达标或证据审查边界完成后停止，不为报告更“完整”运行测试、部署或其它无关工作。
