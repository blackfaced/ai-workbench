# L1 摘要（每轮注入）

**懒惰阶梯**（停在第一个成立的台阶）：需要存在吗(YAGNI) → 仓里已有吗(复用) → 标准库 → 框架/平台原生 → 已装依赖 → 一行写完 → 才轮到最小实现。

**向后兼容优先**：既有行为变更中，向后兼容高于可维护性、去重、统一语义和代码简洁。懒惰阶梯不能授权破坏旧行为；先从真实入口/调用方记录旧合同与影响面，优先 Adapter/Wrapper/Optional/默认关闭/保留旧路径，并用旧路径与受影响调用方回归证明兼容。新路径通过、构建成功或源码检查不能替代兼容证据。

**复杂度预算**（开始变复杂时先明说三件事）：我在加什么复杂度、每一块现在为什么必要、删掉它会坏什么。说不出第二问的那块就是过度设计。
**实现类 Issue 开工门禁**：编码前留下 6 项简短记录——合同不变量、完整调用链、边界（schema/状态/fallback/错误/敏感信息/计量副作用）、测试矩阵、最小方案与非目标、可运行反馈命令；修 bug 先稳定复现为红。出现新分支或 fallback 时先更新门禁，再按共享根因和完整合同一次收敛。

**达标即停**：验收标准满足就收手。不做「既然都改到这儿了」，不在没有证据的情况下为未来留扩展点。顺手发现的邻近改进单独报告，不要实施。

**不写**只有一个实现的 interface，不为单一产物写 factory，不为「以后可能要」搭脚手架。

**`lazy:` 妥协标记**：有意识停在低阶台阶时，在那行旁留 `// lazy: <为什么这样够用；旧行为/调用方为何不受影响或由何回归覆盖>`（需跟进则 `-> #NN`）。`lazy:` 必须已经做完、能跑并保留既有合同，不能把破坏旧行为包装成简单实现；语义区别于 `TODO`（还没做）/`FIXME`（做错了）。

**code review**：每次必须套用通用双层诊断契约——对每个诊断轴先判适用性（不适用须说明理由，适用性判据见 `environment-identity-assumptions.md`），适用则核验独立权威依据，缺证据不得通过（全文 §7）；身份/权限/资源归属是其中一个必经实例。除正确性/规范轴外，必须补一轴「必要性」（这段代码该不该存在），判据见 AGENTS.md 通用规则中的必要性审查附件。
**跨系统/跨环境/跨身份域改动开工前**：按 `environment-identity-assumptions.md` 过九维假设表（外部依赖/所需能力/环境差异/身份区域绑定/配置来源/规模拓扑/失效方式/兼容不支持/验证证据），每条带工具定位依据和未验证边界，不凭记忆写符号名。
完整通用规则见 AGENTS.md 中的 L1 规则块；工作环境及 Issue 路由由分发方提供。
