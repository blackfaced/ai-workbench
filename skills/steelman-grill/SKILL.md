先跑一次 `grilling` 会话：设计树、frontier、按轮提问、等用户确认后才动手——这套骨架一字不改。

本文只加四条 delta，用来堵 grilling 的谄媚缺口：它要求每题给一个推荐答案 `➡️`，而那个推荐天然会顺着用户已经说出口的偏好，于是整棵树可能建在一个从没被质疑过的方向上。**steelman** 是解药——先把一个立场补完整、推到最强，再判断它。

## 1. 开轮前重述问题

展树之前，先用最完整、最有力的方式重述用户真正想解决的问题，并请用户确认。

人会把"嘴上问的"和"真正想解决的"混在一起。问的是"这个 skill 放哪个仓"，真正在解决的可能是"我半年后还改得动它吗"。重述这一步把真实问题捞出来，否则整棵设计树的根就是错的，后面每一轮都在精修一个错误。

## 2. 每题四段式

frontier 上每个问题的推荐答案展开成四段，替换 grilling 的单行 `➡️`：

```
❓ **Q1** — **<问题标题>**：<问题正文，可含多个选项>

🛡️ **支持它的最强论证**：<这条路能拿出的最好证据，说得比它的拥护者更好>
⚔️ **反对它的最强论证**：<最难回答的那个质疑，保持它的全部锋利度>
🔑 **决定性变量**：<哪个变量一变，下面的推荐就翻转>
➡️ **在当前假设下推荐**：<结论 + 理由 + 翻转条件>
```

"双向"指的是 steelman 这个动作施加在两个对象上：用户的倾向被强化一次，反对它的立场被强化一次。执行强化的是 agent 自己，不是让 agent 下场跟用户辩论——最后 agent 手里握着两个最强版本，再做判断。

🛡️ 与 ⚔️ 里写的是**论证**，不是"优点/缺点"清单。优缺点可以并列 happily 共存，论证必须互相攻击才暴露真实分歧。

🔑 是这套格式里最有价值的一段：它把推荐从断言降级为**带前提的条件命题**。用户只要否掉前提，答案自动翻转，不需要跟 agent 争。绝大多数复杂问题看着十几个因素，真正能改变结论的只有一两个——找到它，这一题就问完了。

## 3. 反谄媚纪律

- 推荐依据是论证强度，不是用户已表露的倾向。用户越明显地偏向某一侧，⚔️ 那段就越要写足。
- 每条推荐都写出翻转条件，用户的答案落在翻转条件上时立刻改推荐，并说明改了什么。
- 发现用户的新答案与他此前的决定冲突，先摆出冲突再往下走；不要挑一个顺手的解释闷头继续。
- 事实自己去查（文件、命令、代码、网页），只把**决策**交给用户。用户的既有配置、ADR、历史决定都是事实，会推翻推荐——查它们的成本远低于建错一整棵树。

## 4. 收口：一个关键问题 + 明确判断

frontier 收窄到只剩少数叶子时切换模式：压成**一个**最关键的问题，用户答完立即给判断、理由、下一步行动。

问题选得对，它会难到让人卡住——那正是信号，答案就在它后面。收口时的判断必须落地成可执行的下一步；"视情况而定""都有各自的适用场景"这类回答等于没收口，重新收。

## 出处

steelman 是逻辑学 straw man（稻草人谬误：把对方观点扭曲成弱版本再攻击）的反向操作。四步结构参考数字生命卡兹克 2026-08-18《一个实用的深度思考 Prompt：用"双向钢人论证"让 AI 帮你挖出最本质的答案》，其源头是 Reddit 帖 "Stop asking it for answers. Ask it to steelman your problem first."。本 skill 把那四步嫁接到 grilling 的树形推进上：grilling 保证该问的都问了，steelman 保证每一问都问到底了。
