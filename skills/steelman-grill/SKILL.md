# Steelman Grill

把本 skill 作为已安装 `grilling` skill 的增量层。先遵循它的设计树、frontier、事实查证、逐轮等待和“达成共同理解前不行动”协议；本 skill 只增强每个问题的论证内容，不改变提问调度。若 `grilling` 不可用，说明依赖缺失并停止，不要复制或猜测它的协议。

## 锚定真实问题

开始时用一到两句话，以最完整、有力的方式重述用户真正要解决的决策。只有当重述会改变设计树的根节点时才请用户确认；请求已经清晰时直接推进。

先查文件、代码、ADR、历史决定和其他可验证事实。无法确认的事实写成显式假设，不要把可查事实伪装成需要用户决定的问题；等待事实时，继续询问不依赖它的其他 frontier 决定。

## 批量压测当前 frontier

每轮一次列出当前 frontier 的全部独立决定。不要因为 steelman 内容更长而擅自改回一次一题；依赖本轮其他答案的问题留到下一轮。用户回答后，按 `grilling` 重新计算 frontier。

每个决定只比较当前最强候选与最强替代。存在三个以上选项时，先用一句话淘汰明显被支配的选项；不要用对称篇幅掩盖证据强弱。

同一轮内为每个 frontier 决定重复以下卡片，并用 `---` 分隔：

```text
❓ **Q1** - **<问题标题>**：<会改变后续路径的决策问题和选项>

🛡️ **最强候选的 steelman**：<支持当前最强候选的完整论证>
⚔️ **最强替代的 steelman**：<最难被当前候选回答的替代论证>
🔑 **决定性变量**：<一个可观察、足以翻转结论的变量>
➡️ <当前推荐、核心依据，以及什么条件下改选替代方案>
```

论证必须彼此攻击同一个核心分歧，不能退化成可同时成立的优点/缺点清单。决定性变量必须可观察且真的会翻转推荐；找不到时明确写“尚未发现可信的翻转条件”，不要编造平衡感。

## 反迎合与一致性

- 依据证据和论证强度推荐，不依据用户已表露的倾向。用户越偏向一侧，越要完整呈现最强替代论证。
- 用户答案跨过翻转条件时立即改推荐，并说明是哪条假设改变了。
- 新答案与旧决定冲突时，重新打开受影响的上游节点；先解决冲突，再继续展开设计树。
- 用户尚未表达倾向时，不替用户虚构立场；比较当前证据支持的最强候选与最强替代。

## 收口

当 frontier 为空时，给出明确判断、关键理由、仍成立的假设、翻转条件和一个可执行的下一步；不要用“视情况而定”代替结论。然后请用户确认是否已达成共同理解，确认前不要开始实施。

在 AI Workbench 中只把本流程用于 Admission 之前的 Goal/Contract 收敛。已 admitted 的 Run 由 ExecutionSnapshot、RunLedger 和 Harness Evidence 决定，不通过对话重新解释或扩展。
