# Writing Docs

Domain: coding, research, ops

围绕读者要完成的任务写文档；更新时保留有效结构，把新事实归回原位置。技术方案、验收报告等专用 Skill 负责领域内容与证据要求，本 Skill 负责表达、信息组织和编辑保真。

## 上游与分工

先读取环境中已安装的 Matt Pocock `writing-for-agents`；其 [上游入口](https://github.com/mattpocock/skills/blob/main/skills/productivity/writing-for-agents/SKILL.md) 由上游维护，不复制正文。若本地缺失，可读取该入口并说明来源；无法读取时明确缺失，继续完成不依赖它的工作。

采用其中的信息层次、同概念聚合、单一事实源和裁剪原则，按读者已有知识判断解释是否必要。Matt 的触发、指针和完成条件规则用于编写 agent 指令，不套入面向人的正文。用户目标、项目约定及领域合同决定内容要求，不能为精简删掉必要事实或证据。

## 确定本次改动

先读现有目录、相关章节和权威来源，明确读者要做什么、本次事实改变什么。

| 任务 | 默认做法 |
|---|---|
| 新建 | 选择与读者任务相符的体裁，按内容裁剪模板。 |
| 更新 | 原位修正相关内容，保留未受影响的标题、层级、顺序、术语与资源。模板用于查缺，不自动套版。 |
| 重构 | 在用户要求的范围内调整结构，保留仍有效的事实与引用，说明主要结构变化。 |

校对修正文字与格式；润色改善段落和句子，保留核心论点；论证或结构修订按任务范围处理。需要修订内容时，先核对判断与依据，再调整表达，最后校对格式和引用。

局部更新发现无关的结构或论证问题，交付时简述建议；只有完成本次任务确需调整且现有授权未覆盖时，才提出具体调整请求。以上判断留在工作过程，不为它们新增正文栏目。

## 编辑与归位

- 把新规则放回对应概念、接口或步骤；替换失效表述，并同步受影响的摘要、表格、示例和图。历史事实有保留价值时标明版本，不与当前规则并列为现状。
- 同一规则保留一处详细定义，其他位置只写读者需要的摘要与链接。实施流水、调研过程和工具使用记录放在项目已有记录中；正文留下会改变读者决定或操作的证据。
- 每段回答一个阅读问题，每个新增段提供新事实、必要解释或操作。删除同义复述和没有信息增量的前言、总结；保留适用条件、例外、错误语义和可执行命令。
- 润色与精简时保留作者的选择、理由、代价、反例与未解决问题，沿用观察、推测、已确认结论和建议的确定性。经验只据已提供或可核验的材料表述，不代写亲历。例如“采用异步处理，接受短暂不一致以降低请求延迟”不能改成“采用高效架构，兼顾性能与一致性”。
- 按已读取的段落或 block 修改。文本替换前确认命中位置与预期数量；多个语义不同的位置逐块处理。例如仅修改“重试次数不变”时，不能全文替换“不变”，误伤“接口不变量”。
- 沿用载体对应工具的版本、资源及评论保护机制。改后重新读取；版本冲突或部分成功时先核对当前状态，不按旧定位重复覆盖。标题变化时核验入链，移动内容时核验资源与交叉引用。

## 清楚表达

按读者的共享知识使用术语：同行熟悉且准确的术语直接使用；面向混合读者时，首次用简短白话解释，再沿用术语。省略已知背景，不省略接口合同或验收依据。

借鉴 ASD-STE100 的适用原则：一句表达一个主要意思；写明谁在什么条件下做什么；操作步骤将必要条件放在动作之前；同一概念沿用同一术语。保留 API 字段、命令、状态名和单位的准确拼写。

例如“为保障流程顺利执行，建议在条件具备时进行相关重试操作”应按事实改为“连接超时后重试一次”；事实没有规定次数时，不为了写得具体而编造次数。

中文和普通技术方案按这些原则写，不套英文受控词表或固定句长，也不宣称符合完整 ASD-STE100。用户明确要求英文 STE 合规时，另读取其指定版本的官方标准，核对规则、词表与领域术语；缺少标准或核验依据时明确尚未验证合规。

图、表或交互示例只在能减少理解成本时采用，沿用文档已有载体。短线性步骤使用文字即可，必要决策依据不为压字数移出正文。

## 完成检查

对照修改前后，确认本次需求已覆盖、事实与证据未误改或遗漏、判断及其确定性与取舍未被润色改变、当前口径一致、未受影响内容保持有效、结构变化符合任务、链接和资源可用。篇幅与改动量用于发现异常，不设统一缩短比例。达到这些条件后停止；交付只说明实质改动和未验证项，不把编辑过程再写成文档正文。

需要核对这些原则的来源、适用边界或修改本 Skill 时，读取 [来源与适用范围](references/sources.md)。
