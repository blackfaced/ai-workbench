# 科普概念讲解视频

一个视频围绕一个核心洞察：先建立直觉，再给出适用条件与推导。动画中的每次变化都应帮助解释概念；保留可修改、可复现的代码工程。

## 1. 确定交付范围

从用户请求提取主题、受众、时长、画幅、语言和交付物；缺项采用下表，并简述假设。用户已给出的要求优先。

| 场景 | 默认时长 | 默认画幅 | 叙事范围 |
| --- | --- | --- | --- |
| 短视频或未指定时长 | 60 秒，可按内容调整到 60–90 秒 | 9:16，1080×1920 | 一个概念、一个例子、一个结论 |
| 明确要求完整推导或长讲解 | 5 分钟，可调整到 3–8 分钟 | 16:9，1920×1080 | 同一概念的直觉、推导与验证 |

默认中文，面向该主题入门者；术语出现前补必要前提。仅要脚本或分镜时交付对应文档，不准备渲染环境。明确授权整片制作时，完成分镜后继续制作；用户要求先审分镜时才等待确认。影响主题或结论的歧义需先澄清。

## 2. 核验科学内容

脚本定稿前列出支撑核心洞察的断言，逐项核验定义、公式前提、数值、算法计数与因果关系，说明类比在哪里失效。每条关键断言应有可定位来源、推导或可运行验证；未核实的断言不能当作已知结论进入定稿。

涉及论文、数值演示、复杂度或争议结论时，读 [科学核验方法](references/scientific-checks.md)，使用其中的断言表和验证方法。事实来源优先原论文、教材、官方技术文档；价格、许可、政策和新研究在使用时重新核实。输出质量、代码运行成功与科学准确性分别检查。

## 3. 选择表达方式并写旁白

默认用最小例子逐步解释；适合几何直觉时加连续变换，适合算法时加代码和真实运行结果。用户点名风格、使用绰号或题材需要特定叙事时，只读 [风格库](references/masters-styles.md) 的对应条目；不必为每个视频加载全部风格。

五幕骨架可按篇幅合并：钩子 → 直觉冲突 → 核心洞察 → 验证/推导 → 回响。短版钩子尽量在前 3 秒成立，长版可放宽到 15 秒；段落长短服从理解难度，不固定比例。

逐句写口语旁白。初稿用每秒约 3–4 个中文字估算，另留停顿和看图时间；60 秒片初稿可从 150–180 字起步。数字、英文和公式需按实际读法估时。试读或已有配音时长优先于字数估算，超时优先删减内容。

## 4. 分镜与时间线

读 [分镜格式](references/storyboard-format.md)，建立镜头起止时间、旁白、画面、动画与对应科学断言。短版先复用其中的 60 秒示例结构。

用代码求和各镜时长并检查连续性；镜内动作覆盖到镜头结束，旁白时间锚点落在镜内。制作有声视频时先试读/生成旁白，再据实调整分镜；短镜头不要靠语速加快掩盖超时。复杂镜头用关键帧描述说明观众应看懂什么。

## 5. 选路线、预检并制作

仅在需要渲染时读 [技术管线](references/code2video-pipeline.md) 的所选路线：数学/几何优先 Manim，算法过程可用 Motion Canvas，React 包装可用 Remotion；最终用 FFmpeg 合成。

在技能目录运行对应预检，例如：

```bash
python3 scripts/check_environment.py --route compose --burn-subs --audio
python3 scripts/check_environment.py --route manim --font "Noto Sans SC" --math
```

只检查当前所需路线。缺依赖时说明缺项，使用现有可用路线或保留已完成的脚本/分镜；安装行为遵循项目授权。Manim 开工前用 [视觉模板](assets/manim_house_style.py) 的 `StyleDemo` 验证中文和公式；自定义 TeX 编译器需配置并实测，不能假定自动兼容。

合成调用 [assemble_video.py](scripts/assemble_video.py)：先逐片统一规格，再拼接，所有输入声明后再映射输出。传入明确的 `--resolution` 与 `--fps`；竖屏示例用 `--resolution 1080x1920`。`--bottom-strip` 在目标画布内预留黑条，不增高画布；字幕样式仍需抽帧检查。

## 6. 检查并交付

- 复核最终旁白、图示与科学断言表一致；公式颜色只是辅助，关键对象还要有位置、形状或标签区分。
- 核对镜头总时长、最终尺寸/帧率、音视频与字幕轨；旁白提到的对象出现时机目标误差不超过 0.5 秒。
- 用 `scripts/preview_frames.py <video> -o sheet.jpg` 抽帧初检；它均匀取样，不能证明每个短镜头都检查过。补看镜头边界、关键推导帧并回放整片。
- 竖屏公式优先分步或纵向展开；在实际手机尺寸检查文字、公式和字幕，控制单屏信息量。字幕负责完整句子，画面保留图注和短关键词。
- BGM 是固定降音量并循环；当前脚本不实现动态 ducking。音频滤镜目标 -14 LUFS，不等于测量结果；交付前检查旁白可懂度并测量成片响度。

交付用户请求的 MP4、旁白稿/分镜、关键来源与核验结果，以及渲染工程和版本/命令。素材音轨默认被丢弃，旁白按画面时长补静音或截断；制作时先对齐时长，交付检查不能省略被截断的句尾。标明未执行或未通过的检查，不把预检通过当成完整成片验收。
